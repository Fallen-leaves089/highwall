# HighWall Threat Model

版本：`0.8.0`
范围：HighWall 进程及其 HTTP 入口、上游连接、审计和管理面。

## 1. 安全目标

HighWall 的目标不是让上游应用“自动变安全”，而是在应用前面维持一组明确、可测试、默认拒绝的 L7 不变量：

1. 只有明确允许的 authority、方法、规范化路径和媒体类型才能到达上游；启用来源 ACL 或 Origin 白名单时，还必须满足对应约束。
2. 请求和响应 framing 不允许由多个组件各自解释。
3. 单个客户端不能无限消耗连接、内存、时间或审计磁盘。
4. 网关自身不把 Cookie、Authorization、查询串、请求体或管理 token 写进审计。
5. 明显包含私钥、常见访问 token 或调试栈的上游响应体前缀或响应头不会在 `block` 模式下被转发；`Set-Cookie` 固定排除以避免登录会话误报。
6. 管理面不能被外部网络触达。
7. 配置或审计不可用时失败关闭。
8. 明确的只读路由和高风险写方法不能到达上游；超限并发在上游前被拒绝。
9. 配置了钉扎的静态响应被替换时，能够检测或在转发前阻断；上游持续故障不会无限放大。
10. 显式配置的诱饵路径不会到达上游，命中可被独立审计，并可立即封禁来源而不采集请求内容。
11. 对快速、重复的攻击流量做多信号关联和两阶段遏制：疑似阶段先限速 5 分钟，确认后写入有界标记并施加 15 分钟慢速窗口，为防御者争取响应时间。该目标是增加攻击成本，不是保证攻击者一定被拖住 15 分钟。
12. 对到达 HighWall 的 L7 饱和信号发出可异步送达的 DDoS 告警，并在载荷中给出 5 分钟响应窗口；告警不替代带宽清洗、运营商处置或独立心跳。

## 2. 资产

- 上游应用的业务数据和会话；
- 上游服务的可用性；
- 配置中的允许列表、WAF 模式、TLS 参数和审计策略；
- 管理 token、TLS 私钥和上游可能使用的凭证；
- 审计记录、指标和运行状态；
- HighWall 进程及其文件完整性。
- 静态响应的已审核 SHA-256 基线。
- 蜜罐路径、静态诱饵内容和首击封禁配置。
- 攻击者指纹、持久标记、慢速槽位和告警去重状态。
- Webhook 地址、Bearer token 和外部告警接收端。

## 3. 信任边界

```text
untrusted client
    |  HTTP/1.1
    v
[HighWall proxy listener]  <-- client ACL/connection limits/rate/ban
    |                      <-- fingerprint + threat score/throttle/tarpit/mark
    |                      <-- Origin + Host/method/path/WAF/body
    |                      <-- L7 DDoS signals
    |  loopback or private network
    v
[upstream application]

[alert dispatcher] --HTTPS webhook--> [external NOC / on-call receiver]

[loopback admin listener] <-- separate port, bearer token
    |
[operator workstation / local agent]
```

边界假设：

- 客户端网络不可信；请求头、路径、body 和 TLS 元数据都可能被伪造。
- 客户端 CIDR ACL 只覆盖到达 HighWall 的 HTTP 连接。启用时，错误配置可信代理或过宽 CIDR 会破坏来源判断。
- `allowed_origins` 是浏览器写请求的来源约束，不是用户认证；非浏览器客户端必须在业务层单独鉴权。
- 上游应只接受来自 HighWall 的连接；否则攻击者可绕过所有 L7 策略。
- 管理面和 HighWall 文件系统必须由运维账户和 ACL 保护。
- 运行 HighWall 的主机操作系统、Python 运行时和上游应用不在本项目的修补范围内。
- 告警接收端和出站 DNS/TLS 链路属于部署者控制的外部信任边界；Webhook 接收端被攻陷或记录完整载荷时，HighWall 无法提供额外保护。

## 4. 攻击者能力

### 纳入考虑

- 远程发送任意 HTTP/1.x 请求（包括畸形头、超长行、慢速发送、重复头、编码路径）；
- 知道或猜中 Host、路径和常见业务端点；
- 在速率限制内反复请求；
- 尝试利用上游的授权缺陷、IDOR、默认口令或已知漏洞（HighWall 只能降低暴露面，不能修复业务逻辑）；
- 伪造 `Origin`、`Sec-Fetch-Site` 或缺少来源头的跨站写请求（仅在配置 Origin 白名单时纳入强制校验）；
- 从非允许客户端网段发起 HTTP 扫描或探测（仅在配置客户端 ACL 时生效）；
- 通过错误配置的可信代理头伪装客户端 IP；
- 触发上游慢响应、超大响应或畸形 framing；
- 反复触发协议/策略错误，尝试消耗连接或探测规则（受单 IP 并发和临时封禁约束）；
- 尝试通过应用接口执行未授权的写入、删除或配置变更（仅当路由/只读策略正确覆盖时被 L7 阻断）；
- 让上游持续超时、返回 5xx 或占用昂贵接口，放大可用性故障；
- 同时发起大量已建立连接或慢请求，消耗连接、在途请求和路由并发槽位。
- 扫描常见敏感路径、默认管理入口或不存在的端点，尝试发现可攻击面。
- 使用自动化脚本或 AI 驱动的快速探测，轮换请求路径、Header、TLS 形状或来源地址，试图在短时间内完成枚举和利用。
- 制造大量 L7 请求、拒绝、连接饱和、TLS 握手失败或上游错误，试图耗尽网关或上游容量。

### 不纳入考虑（必须由其他层解决）

- 已取得运行主机 root/Administrator、可读进程内存、可修改 HighWall 二进制或配置的攻击者；
- 可嗅探 HighWall 所在 netns 内明文回环流量的同主机进程；
- WSL/虚拟机内已被攻陷、且与 HighWall 共享可写目录或网络命名空间的攻击者；
- 大流量 DDoS、链路拥塞和上游容量耗尽；
- 已取得主机写权限后部署的勒索软件、擦除程序或备份破坏；
- 供应链投毒、Python 解释器后门、证书颁发机构被攻陷；
- 上游应用自身把密钥写入响应、日志或前端。

## 5. 主要威胁与控制

| 威胁 | 控制 | 残余风险 |
|---|---|---|
| HTTP request smuggling / CL.TE / TE.CL | 只接受单一显式 `Content-Length`；拒绝 `Transfer-Encoding`、`TE`、`Trailer`；重建上游请求 framing | 上游若存在旁路端口，仍可被直接攻击 |
| Host header 攻击/虚拟主机绕过 | `allowed_hosts` 精确 authority 匹配；重复 Host 拒绝；NFKC/大小写归一化 | 配置过宽的 allowlist 会降低效果 |
| 路径穿越、路由大小写与编码歧义 | 最多四轮严格 UTF-8 解码；拒绝编码分隔符、反斜杠、控制字符和点段；默认拒绝分号路径参数、尾随点/空格；ACL、路由、只读和完整性统一使用规范化且大小写不敏感的路径 | 显式打开兼容开关会重新引入歧义；上游若再做非标准路径解释，仍可能有差异 |
| XSS / SQLi / JNDI / SSRF 输入 | 保守签名扫描路径、查询、头和允许的 body；覆盖注释绕过、命令分隔符、事件处理器以及整数/十六进制/IPv6 回环地址；`detect`/`block` 可选 | 签名不完备，存在漏报和误报；不能代替参数化查询、输出编码和服务端 SSRF 白名单 |
| 请求体 charset/BOM/NUL 混淆 | body 声明 charset 只接受 UTF-8/ASCII；拒绝 UTF-16 BOM 和其他歧义前缀，拒绝 NUL；WAF 扫描重复解码视图 | 上游若自行接受非标准编码，网关与上游的解释仍可能不同 |
| 慢客户端 / Slowloris | 请求头绝对期限、请求体绝对期限、发送期限 | 应用层 DDoS 仍可能耗尽上游或带宽 |
| 慢上游 / 无限 chunk | `connect_timeout`、`read_timeout`、`total_timeout`，以及看门狗关闭连接 | DNS 解析阻塞不完全受 socket 超时控制；上游 DNS 应稳定可信 |
| 超大请求/响应 | 行、头、体、响应字节和连接数上限；内存预算检查 | 合法大文件下载需调整上限，可能增加内存压力 |
| 响应拆分/头注入 | 上游头名/值校验、逐跳头清理、`Content-Length` 重建、安全头覆盖 | 上游 `Set-Cookie` 等业务头仍按原样转发 |
| 客户端伪造 `X-Forwarded-*` | 默认剥离并由网关重写；仅在配置可信代理时解析 XFF 链 | 配置错误地信任过宽网段会破坏客户端识别 |
| 来源网段不受限 | 可选 `allowed_client_networks` / `denied_client_networks`，拒绝优先 | 只约束已到达网关的 HTTP；不能替代防火墙、DNS 控制或 RPC 隔离 |
| 未授权或误触发的写操作/删除接口 | 全局或路由级 `read_only`；路由方法子集、来源 CIDR、请求体上限 | 只按 HTTP 方法判断；GET 副作用、上游授权漏洞和旁路入口仍可造成破坏 |
| CSRF / 跨站写请求 | 可选 `allowed_origins`；写方法要求 Origin 匹配，并拒绝 `Sec-Fetch-Site: cross-site` | 非浏览器客户端可伪造 Origin；真正的授权仍由上游负责 |
| 上游把秘密或调试信息写回客户端 | 响应体有界前缀和响应头 DLP，不按媒体类型跳过，尝试 UTF-8/Latin-1/UTF-16；`block` 模式返回 502 而不转发命中内容；强制上游 identity 编码并拒绝压缩响应 | 启发式规则只检查有界前缀，任意编码、分片、二进制或流式内容仍可能漏报；`Set-Cookie` 被有意排除；可能误报 |
| 静态页面/关键响应被替换 | 对精确 GET 路径钉扎状态码和响应体 SHA-256；`block` 模式不转发不匹配内容 | 仅覆盖配置的静态响应；基线被篡改、动态页面、HEAD、查询串和未配置路径不受保护 |
| 上游故障放大 / 慢上游拖垮线程 | 熔断阈值、冷却、有界半开探针；连接/读取/总超时 | 熔断期间主动返回 503；不是容量型 DDoS 防护或上游高可用 |
| 连接/在途请求/昂贵接口耗尽 | 全局在途上限、路由并发槽位、连接上限和临时封禁；超限在上游前拒绝 | 拒绝本身会占用有限线程；带宽、内核连接表和上游容量仍需主机/网络层保护 |
| 单 IP 连接耗尽、昂贵路由滥用或反复探测 | `max_connections_per_ip`、全局与路由令牌桶限速、时间窗内累计违规后的临时封禁 | 不是抗容量型 DDoS；NAT/共享出口可能被连带封禁，状态重启即丢失 |
| 敏感路径探测 / 扫描器枚举 | 可选精确路径蜜罐：内置常见路径模板、本地静态响应、不访问上游、独立审计、首击封禁、可选有界拖延 | 只覆盖配置路径，可能被指纹识别；预设可能与真实业务路径冲突，首击封禁可能连带 NAT 来源，拖延不能替代速率限制 |
| 管理 token 泄漏 | 仅回环、Bearer 校验、常量时间摘要比较、token 不进入 Runtime repr/审计 | 本机被攻陷、环境变量可读的攻击者仍可拿到 |
| 管理面被外部访问 | 只允许 loopback listener；peer 和 Host 双重检查；不提供端口转发 | 运维错误地暴露端口会绕过假设 |
| 快速自动化/AI 驱动攻击、短时间枚举 | HTTP Header 形状、TLS ClientHello 和 `/24`/`/64` 来源前缀多信号关联；疑似先限速 5 分钟，确认后写入有界标记并施加 15 分钟慢速窗口；慢速槽位按攻击者和全局限额 | 指纹可被伪造或轮换；共享 NAT 会误伤；客户端可关闭连接或并发重试；容量估算不是 SLA |
| L7 DDoS / 上游饱和 | 聚合请求速率、拒绝比例、连接饱和度、TLS 失败和上游错误；多信号触发 `ddos_suspected`，300 秒后升级，恢复时发事件；异步 Webhook 通知 NOC | 只覆盖到达 HighWall 的 L7 信号，不识别真实来源；带宽型 L3/L4、SYN flood 和运营商侧拥塞不在范围内；主机饱和时可能先失去可达性 |
| 持久标记被误用或篡改 | 标记只含派生指纹、分数、信号和可选来源；TTL、容量上限、原子写入、普通文件/符号链接检查；形状匹配只作为信号，不自动确认 | 共享出口、代理池和正常自动化可能被误标；能写数据目录的攻击者可删除或伪造标记；标记不是认证或永久封禁源 |
| 告警载荷泄漏或丢失 | 默认不含路径、查询串、Cookie、Authorization、请求体或客户端 IP；HTTPS、Bearer token、禁止重定向、队列上限和失败重试 | 接收端日志和凭据仍需保护；队列满或网络故障会丢告警；Webhook 不能替代独立心跳 |
| 审计日志注入/泄密 | 固定字段、路径控制字符清洗、查询串剥离、不记录 Cookie/Authorization/body；路径默认 `redact`，可选 `hash`/`exact`、0600、轮转 | 审计目录 ACL 错误时仍可能被读取或删除；`exact` 会把路径本身写入日志 |
| TLS 降级与缺少 HSTS | TLS 启用时默认注入一年期 HSTS；显式安全头仍可覆盖 | 不修复证书错误，也不阻止首次明文访问或违背客户端策略的访问 |
| 配置替换/符号链接 | 配置必须是普通文件；拒绝符号链接/重解析点；大小和 JSON 深度限制 | 父目录被攻陷、TOCTOU 或管理员故意放宽仍可绕过 |
| 审计路径替换 | 启动和写入前检查普通文件/符号链接；Unix 使用 `O_NOFOLLOW` | Windows 缺少等价原子 no-follow 时，目录 ACL 仍是最后防线 |
| WebSocket/Upgrade 走私 | 直接拒绝 Upgrade、TE、Expect | 需要实时双向通信的功能必须使用专门的流式代理，而不是本版本 |

## 6. 关键安全不变量

- `RequestHead.content_length` 只能来自一个合法十进制 `Content-Length`，并在转发前被网关替换。
- 路径默认拒绝分号参数、尾随点和尾随空格；Host/来源 ACL 先执行，路由、只读和完整性判断使用规范化且大小写不敏感的 `route_path`，上游目标保留原始查询串语义。
- 普通上游请求的 body 必须有允许的 Content-Type；声明 charset 只接受 UTF-8/ASCII，UTF-16 BOM、其他歧义前缀和 NUL 被拒绝。GET/HEAD body 默认拒绝。蜜罐命中路径例外：body 按声明长度分块丢弃，不转发、不扫描、不记录。
- 上游响应中的 `Content-Length` 必须唯一且为十进制；与 `Transfer-Encoding` 不能共存；只接受 `chunked`。
- 响应使用网关自己的 `Date`、`Connection` 和 `Content-Length`；`Server` 默认 `HighWall`，蜜罐可使用配置的诱饵值。
- 客户端 ACL 的拒绝列表优先于允许列表；空允许列表表示不按网段限制。
- 配置 `allowed_origins` 后，写方法必须带规范且允许的 Origin；`Sec-Fetch-Site: cross-site` 的写请求被拒绝。
- `read_only` 或路由方法约束必须在读取普通上游请求体、连接上游之前拒绝不安全的写方法；蜜罐命中路径是显式例外。
- 路由按最长路径前缀选择；配置了 `rate` 的路由使用独立令牌桶，超限返回 429 和 `Retry-After`；空的路由来源列表是配置错误，不得解释为“不限制”。
- 完整性钉扎只对精确 GET 路径和配置状态码生效；`block` 模式绝不转发不匹配的响应体。
- 全局在途和路由并发均使用非阻塞槽位；超限返回 503，不排队等待上游。
- 熔断打开时拒绝上游调用并返回 503；半开探针数量有上限，过期请求不能改变新状态。
- DLP 扫描响应的 `response_scan_max_bytes` 前缀和响应头，媒体类型不构成免扫条件，并尝试 UTF-8/Latin-1/UTF-16；`Set-Cookie` 固定排除；上游压缩响应不会绕过扫描，而是直接返回 502。
- 管理 token 长度 32–512，只从指定环境变量读取；管理面只允许 loopback。
- 审计记录不包含查询串、Cookie、Authorization 或请求体；路径默认经解码、清洗和敏感段脱敏，`hash`、`exact` 只能显式启用。
- TLS 启用且未显式配置 HSTS 时，响应自动带 `Strict-Transport-Security: max-age=31536000`。
- TLS 握手在工作线程中执行，受 `handshake_timeout` 约束；慢握手只占用一个连接槽，不阻塞新的 accept。连接或 IP 槽位满载时，TLS 监听直接关闭连接。
- 蜜罐匹配在客户端 ACL 和 Host 之后、普通方法/路径/WAF 之前；命中绝不调用上游，响应只来自配置，且不反射或记录请求体、Header、Cookie 或查询串。
- 蜜罐响应体、路由数、Header 数、延迟和封禁表均有上限；`ban_seconds=0` 必须明确关闭首击封禁。
- 指纹只从 Header 形状、TLS ClientHello 和来源前缀派生；Cookie、Authorization、查询串、原始路径、请求体和 token 不进入指纹或持久标记；形状相同只增加 `shape_match` 信号，不能单独自动确认。
- 疑似窗口默认 300 秒，确认窗口默认 900 秒；确认标记有 TTL 和容量上限，慢速槽位有单攻击者和全局限额，满槽返回 429 且不继续占用线程。
- 慢速通道由 HighWall 本地返回，不访问上游；从响应头发送完成到最后一个响应体分块完成按 `tarpit_hold_seconds` 调度，并受 `max_tarpit_hold_seconds` 约束。它只能拖慢读取完整响应的客户端，不能阻止攻击者关闭连接或轮换指纹。
- DDoS 检测只对到达 HighWall 的 L7 信号做启发式聚合；`containment_window_seconds=300` 是建议响应窗口，不是自动清洗或可用性保证。
- Webhook 使用有界异步队列和有限重试，不阻塞请求线程；告警发送失败、队列满或接收端不可用必须由外部心跳和值班流程补偿。
- 配置、审计、证书路径不可用时启动失败，不降级为“全部放行”。

## 7. 明确不适用的场景

### 沙箱攻防/主机被攻陷

如果攻击者已经在同一主机上取得 root、可读取 HighWall 环境变量、可 ptrace/读进程内存、可捕获回环明文、可写配置目录或可挂载宿主文件系统，那么 HighWall 的 L7 策略不能建立可信边界。正确顺序是：

1. 用户分离和非 root 运行；
2. 独立 mount/pid/net namespace；
3. 文件 ACL 和密钥隔离；
4. 网络隔离和最小出网；
5. 再把 HighWall 作为应用入口防线。

### 需要“拿到密钥才算赢”的业务演练

HighWall 不是业务应用本身，也不生成或保管业务密钥。若演练目标是“攻破浏览器会话/拿到应用密钥”，需要在上游应用中实现认证、授权、密钥生命周期和最小权限；HighWall 只能帮助减少入口攻击面、记录请求和拦截部分明显 payload。

### DDoS

HighWall 的 L7 告警、连接限制和速率限制是应用层保护，不是容量防御。`ddos_suspected` / `ddos_escalated` 只说明到达网关的请求、拒绝、连接、TLS 或上游错误信号异常；如果攻击流量在网关之前或链路层饱和，HighWall 可能根本收不到请求，也无法发出告警。

公网部署必须结合云清洗、运营商联动、上游限流、主机防火墙和容量规划，并配置独立于 HighWall 主机的主动心跳。收到告警后，防御者应在约 5 分钟内确认 CDN/清洗中心状态、上游容量和审计证据；该窗口不是自动处置承诺。L3/L4 清洗和真实来源识别不在本项目范围内。

### 高交互蜜罐与取证执行

HighWall 蜜罐只提供配置内的静态诱饵和命中信号。它不执行上传代码、不开放 shell、不模拟数据库、不采集完整 payload，也不做反制。需要高交互取证时，应使用隔离虚拟机、专用传感器和独立网络，并把 HighWall 仅作为入口告警层。

### 勒索软件、擦除和备份破坏

高防墙只看到 HTTP 请求。攻击者若已通过钓鱼、远程管理、供应链或本地提权取得主机写权限，可以直接删除文件、加密磁盘或破坏备份，L7 策略无法建立保护边界。必须使用低权限账户、EDR/Defender、受控文件夹、离线/不可变备份和恢复演练；`scripts/host-audit.ps1` 只能提供只读可见性，不能修复。

### GET 副作用

`read_only` 只按 HTTP 方法阻断写操作。如果上游把删除、转账、审批或配置变更实现为 GET，HighWall 无法仅凭方法识别。必须在业务侧改为正确的方法语义并做授权，或将高风险前缀完全移出公网入口。

### DNS 隧道、任意 TCP/UDP 与非 HTTP 服务

HighWall 只监听和检查 HTTP 流量。DNS 查询、原始套接字、RPC、数据库协议、主机出站流量和同机进程边界都需要主机防火墙、netns、DNS 策略或用户隔离处理；应用层 CIDR ACL 不能替代这些控制。

## 8. 验证与发布要求

发布前至少执行：

```powershell
python -m compileall -q highwall
python -m unittest discover -s tests -v
python -m highwall check -c config.example.json
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\host-audit.ps1 -Json
```

测试必须只使用回环/临时端口；任何修改防火墙、端口转发、生产配置或外部上游的操作都需要单独确认。
