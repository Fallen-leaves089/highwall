# HighWall 护栏架构（L5 + H2/H3）

- 状态：B+D-4 原生数据面已实现并通过本地/串联回归；DSH 首轮独立验收完成，r5 定向复测为 0 Critical/0 High、7/8 定向关闭，HWA-11 随后在 r6 窄范围定向关闭；完整残余项仍未关闭，还不能标记为生产完成
- 基线版本：`0.12.0.dev0`（未发布）
- 更新时间：`2026-11-01`
- 适用范围：HighWall、L4Wall、L5Wall、原生 B+D-4 数据面和标准部署拓扑

## 0. 结论先行

1. **最终形态锁定 B+D-4**：L5 和 L7 在同一个原生模块化网关内完成，避免多级代理导致指纹丢失、协议降级和策略分叉。
2. **B+D-1 只做快速上线通道**：先提供可验证的 L5 终止和 H1 完整防护，H2/H3 只能按实际覆盖等级标注，不能把透传写成完整检查。
3. **B+D-3 只做迁移影子验证**：两套数据面同时观察，但不能同时拥有封禁写权限。
4. **L5 必须掌握客户端 TLS 终止点**：如果 HAProxy/Envoy 先终止 TLS，后面的组件拿不到真实客户端的 JA3/JA4；此时只能把它当 L4/TCP 入口，或明确接受指纹丢失。
5. **低误伤优先靠限制封禁范围和分级处置**：检测可以使用 `/24`、`/64` 关联，自动封禁默认只封精确 IP；前缀封禁必须显式开启或人工批准。
6. **危险指令拒绝是独立的 Safe Ops 控制面**：请求层只能拒绝危险 HTTP 操作，不能替代业务授权；运维层必须默认拒绝破坏性动作。
7. **不承诺绝对无漏洞**：目标是让每个已知入口都有归属、默认拒绝、资源上限、审计、测试和回滚，而不是声称已经堵住未知漏洞。

## 1. 设计目标

项目按三条线推进：

```text
已能挡：Python H1 严格防护 + L4Wall 连接防护 + 独立 L5Wall C1 入口
已挡全：原生 L5/H1/H2/H3 数据面，H1/H2/H3 按 C3 声明
继续挡准：多信号 Agent 防御、分级处置、低误伤和 DSH 完整残余项复核
```

不可妥协的安全属性：

- 不确定的解析结果不进入上游；未知协议、未知 ALPN、重复 framing、非法状态转换全部拒绝。
- 不支持的能力明确失败，不静默降级到更弱的协议或更宽的策略。
- 配置、审计、策略或审批依赖不可用时，安全决策失败关闭。
- 网关不采集 Cookie、Authorization、请求体原文、原始查询串等敏感内容到长期审计。
- 单个来源不能无限消耗连接、流、内存、磁盘或慢速槽位。
- 高置信度已知攻击可以先阻断请求；低置信度行为异常先观察、挑战或限速，不能直接大范围封禁。
- 所有自动封禁有 TTL、容量上限、明确范围、可撤销入口和审计记录。
- 运维操作默认假设人会犯错、Agent 会误判、输入可能被提示注入污染；破坏性操作默认拒绝。

| 指纹与封禁 | 精确客户端地址 + 请求形状生成执法键，前缀 + 形状仅做关联；本地 `offenders.json` | 多实例没有单写者；历史前缀记录不升级为精确封禁 | 检测键与封禁键分离；状态服务单写者 |
| 管理面 | 回环 HTTP + Bearer token，默认关闭；`highwall ops preview` 可只读预演类型化计划 | 没有 Safe Ops 执行器、签名批准或自动回滚 | 管理面保持非公网；执行器上线前 R2/R3 默认拒绝 |
| 告警 | 异步 Webhook，失败不阻塞请求 | Webhook 失败依赖外部心跳补偿 | 保持告警非阻塞，但必须监控告警链路自身 |

当前最重要的安全教训是：**关闭评分开关不能跳过已有显式封禁**。任何优化性能或简化路径的改动，都必须先证明不会变成 fail-open。

## 3. 威胁模型

### 3.1 信任边界

```text
不可信客户端 / 自动化 Agent
        |
        v
[DNS / CDN / 云清洗 / 主机防火墙]
        |
        v
[L5 入口：TLS/QUIC 终止、SNI、ALPN、mTLS、指纹、握手限额]
        |
        v
[原生策略执行核心：协议解析、归一化、路由、WAF/DLP、限速、封禁]
        |
        v
[上游应用：只允许原生核心访问]

独立控制面：
  [策略编译器/复杂 WAF 服务]  [风险状态单写者]  [审计/告警]  [Safe Ops]
```

边界规则：

- 客户端提交的 `X-Forwarded-*`、`Forwarded`、来源 IP、协议元数据一律不可信。
- 只有 L5 入口可以写入可信客户端地址和 L5 指纹；下游不得重新解释。
- 上游只能接受原生核心的连接；直连上游等同于绕过全部策略。
- 策略服务、风险状态服务和管理面不能暴露到公网。
- Safe Ops 的授权来自明确的人类意图，不来自网页内容、日志、模型输出或 Agent 自述。

### 3.2 纳入考虑的攻击者

- 远程发送任意 H1/H2/H3 请求、畸形帧、慢速连接和协议状态攻击。
- 具有多个 IP、代理池、云主机或共享 NAT 的自动化 Agent。
- 了解策略、低频慢速、只探测少量路径的定向 Agent。
- 通过伪造 Header、SNI、UA、浏览器形状逃避简单指纹的客户端。
- 误操作的人和误判的 AI Agent：删除数据、覆盖配置、修改防火墙、导出密钥、执行未审计脚本。
- 供应链或依赖被污染后，利用管理面、更新链路或策略下发链路扩大影响。

### 3.3 明确不纳入

- 带宽型 DDoS、运营商拥塞、链路层攻击。
- 已取得主机 root/Administrator、可读写进程内存或可绕过网络拓扑的攻击者。
- 上游业务认证、授权、IDOR、密钥生命周期和数据库约束。
- 端点恶意软件、勒索软件和物理访问。

这些需要清洗中心、EDR、最小权限、不可变备份、网络隔离和业务侧修复，不能被一个 L7 网关替代。

## 4. 目标架构：B+D-4

### 4.1 组件职责

**原生核心（最终）**

- 终止 TCP/TLS/QUIC。
- 完成 H1/H2/H3 严格解析、状态机校验和规范化。
- 执行连接、流、请求、响应、慢速通道和封禁预算。
- 生成稳定的协议指纹和 L5 元数据。
- 执行本地编译策略快照和缓存的风险状态。
- 生成不可变审计事件和有界指标。

**Python HighWall 策略服务**

- 保留复杂 WAF、DLP、规则解释、配置编译和测试 oracle 能力。
- 不直接面对公网，不持有唯一封禁写权限。
- 向原生核心下发带版本号和签名的策略快照。
- 复杂正文检查可以异步或流式调用，但必须有超时、字节上限和失败关闭语义。

**风险状态服务**

- 单机使用 SQLite WAL；多机使用 Redis 或专用服务。
- 只有一个写者；其他节点只读或提交候选事件。
- 保存 actor、来源、原因、阶段、分数、TTL、版本、来源节点和审批引用。
- 不保存 Cookie、Authorization、原始请求体或原始查询串。

**审计与告警**

- 审计写入独立、受 ACL 保护的追加式存储；生产建议哈希链或 WORM。
- 告警异步发送，不能阻塞主请求；但必须监控发送失败、队列深度和最后成功时间。
- 告警链路与 HighWall 进程分离，避免网关失联时告警一起消失。

**L4Wall**

- 继续作为连接级独立防线，负责连接准入、速率、字节预算和粗粒度封禁。
- B+D-4 合并的是 L5/L7 数据面，不意味着取消网络边缘的 DDoS 清洗和主机防火墙。
- L4Wall 与原生核心的封禁同步必须经过单写者，不能双方直接写同一个 JSON 文件。

**L5Wall 子项目**

- L5 建议按 L4Wall 的方式独立为 `subprojects/l5wall`，拥有自己的版本号、测试矩阵、威胁模型、部署说明和发布产物。
- L5Wall 的职责边界是 TLS/QUIC 终止、SNI、ALPN、mTLS、握手预算、证书生命周期和 L5 指纹；不负责 HTTP 路由、WAF 或 DLP。
- 对外只暴露版本化的 L5 元数据和决策接口；HighWall/原生 L7 核心不得直接解析 L5Wall 内部状态。
- B+D-1 可以把它作为独立进程串联；B+D-4 可以把同一模块链接/嵌入原生核心，避免额外网络跳转，但源码和接口边界仍然独立。
- L5Wall 必须先于边缘代理声明“谁终止 TLS”；如果 HAProxy/Envoy 已经终止 TLS，L5Wall 不能再声称拿到真实客户端指纹。

### 4.2 请求路径

```text
接受连接
  -> 连接/来源/握手预算
  -> SNI/Host/ALPN/mTLS 策略
  -> H1/H2/H3 严格解析
  -> 规范化请求对象
  -> 路由与方法/路径/媒体类型策略
  -> Agent 风险评分与分级处置
  -> WAF/DLP/完整性检查
  -> 有界上游连接
  -> 响应 framing/DLP/安全头
  -> 审计、指标、告警
```

任何一步出现歧义，默认不进入下一步。只有明确的、可解释的 allow 决策才能到达上游。

### 4.3 覆盖等级

支持 H2/H3 必须按以下等级声明，不能混用：

| 等级 | 含义 | 是否算完整防护 |
|---|---|---|
| C0 | 加密透传，只做 TCP/UDP 转发 | 否 |
| C1 | 终止协议，读取基本元数据 | 否，只能算接入 |
| C2 | 严格解析、状态机校验、资源上限、路由 | 部分 |
| C3 | 请求/响应头与有界正文策略、WAF/DLP | 是，按路由声明 |
| C4 | 流式正文、WebSocket/gRPC、trailers、长连接完整策略 | 是，最高等级 |

当前原生核心的 H1/H2/H3 可按 C3 声明：解析、策略、资源上限和有界正文检查均已实现。C4 尚未声明，因为真实 WebSocket 端到端、流式背压饱和、QPACK 阻塞和高强度慢速流控测试仍有未覆盖项。

## 5. L5 深度要求

这里的 L5 指 TLS/会话建立层，不是登录 Cookie/JWT 层。

### 5.1 TLS 与握手

- TLS 1.3 默认；TLS 1.2 仅在显式配置且使用 AEAD cipher 时允许；TLS 1.0/1.1/SSLv3 拒绝。
- 命名虚拟主机要求 SNI；缺少 SNI、SNI 与 HTTP Host 不一致时拒绝。
- ALPN 使用显式 allowlist；未知协议、缺失协议、协商失败时拒绝，不静默回落到 H1。
- 支持 mTLS 的 `off`、`optional`、`required` 三档；required 路由必须验证证书链、EKU、SAN 和吊销状态。
- 不把 CN 当作唯一身份；客户端证书身份必须映射到明确的主体和授权策略。
- 记录客户端 JA3、JA4；H2 记录 SETTINGS/窗口/优先级等指纹；H3 记录 QUIC 传输参数和 H3 设置。JA4S 只用于服务端/上游资产识别，不能当作客户端身份。
- 指纹只是相关性信号，不是身份证明，不能单独作为封禁依据。
- 0-RTT 默认拒绝；如启用，只允许幂等方法和可重放安全的路由，并做 anti-replay。
- 会话票据密钥定期轮换；证书和密钥热更新必须原子替换，失败保留旧版本并向告警系统报告。
- 证书过期、链不完整、私钥不可读、SAN 不匹配或吊销检查失败时，按配置拒绝，不降级到明文。

### 5.2 握手资源与异常

- 每来源握手并发、每秒握手数、总握手并发和握手超时都有上限。
- 限制 ClientHello 大小、记录大小、扩展数量、分片异常和重复 extension。
- 握手失败率进入 DDoS 信号，但必须与真实客户端错误区分。
- QUIC 必须实现地址验证、Retry、放大限制、连接 ID 轮换和迁移策略。
- QUIC 的 Initial 解密、QPACK 和 H3 控制流必须有独立预算，避免 UDP 放大和内存耗尽。

### 5.3 证书与密钥生命周期

- 启动时校验证书链、有效期、SAN、私钥权限和配置一致性。
- 轮换前先在隔离端口做新证书握手验证，再原子切换。
- 到期前分级告警：至少提前 30 天、7 天、1 天；到期即拒绝新握手。
- 私钥不能进入日志、审计、配置摘要或告警载荷。

## 6. H2/H3 覆盖要求

| 协议 | 终止 | 严格解析 | 路由/WAF | 流式/DLP | 当前声明 |
|---|---|---|---|---|---|
| H1 | 原生核心/Python | 已有 | 已有 | 有界缓冲 | C3；C4 继续回归 |
| H2 | 原生核心 | 帧/流状态机 | 已实现 | C3 有界缓冲 | C3；C4 待补 |
| H3/QUIC | 原生核心 | QUIC/H3 状态机 | 已实现 | C3 有界缓冲 | C3；C4 待补 |
| WebSocket | 原生 H1 显式路由 | 帧/长度/子协议 | 已实现 | 有界消息检查 | C3；真实端到端待补 |
| gRPC | H2/H3 原生 | trailers/压缩/deadline | 已实现 | 有界消息检查 | C3；C4 待补 |

### 6.1 HTTP/2 必须覆盖

- 连接前言、SETTINGS、ACK、窗口更新、GOAWAY、RST_STREAM 的合法状态转换。
- 最大并发流、每流头部列表大小、HPACK 动态表、CONTINUATION 数、PING 速率和 RST 速率。
- Rapid Reset、CONTINUATION flood、HPACK bomb、窗口耗尽、流耗尽和 ping flood。
- h2c 默认拒绝；只允许显式配置的私网或测试场景。
- 请求头规范化后进入统一策略；伪头、重复头、非法 `:authority`、`content-length` 冲突拒绝。
- 响应 trailers、gRPC 状态和压缩不得成为绕过 DLP 的通道。

### 6.2 HTTP/3 必须覆盖

- QUIC v1/v2、Initial/Handshake/1-RTT 包、Retry、地址验证和放大限制。
- 连接迁移、连接 ID、无状态重置和 0-RTT 重放。
- QPACK 动态表上限、阻塞流、H3 控制流、SETTINGS、GOAWAY 和未知帧。
- H3 只允许 TLS 1.3；不支持时明确拒绝，不把请求降级到其他协议。
- UDP 入口必须有独立速率、并发、包大小和内存预算，不能与 TCP 共用无界队列。

### 6.3 WebSocket 与 gRPC

- WebSocket 只允许显式路由、显式 Origin、显式子协议；默认拒绝 Upgrade 和 CONNECT。
- 限制握手、帧大小、消息大小、空闲时间和每连接消息速率。
- 消息检查可在有界窗口内做 WAF/DLP；不能检查时必须由路由明确接受仅传输风险。
- gRPC 必须解析 trailers、状态码、压缩和 deadline；不能因为二进制正文而整条绕过。

## 7. AI Agent 防御

### 7.1 设计立场

Agent 防御的目标不是识别某个模型，而是提高自动化滥用的成本和可见性。Agent 可以换 IP、换 UA、换浏览器、复用真实 TLS 栈，因此任何单一信号都不够。

### 7.2 信号类别

| 类别 | 可用信号 | 限制 |
|---|---|---|
| 传输 | 客户端 JA3/JA4、ALPN、H2 指纹、QUIC 参数 | 可伪造或复用；不能单独定性 |
| 协议形状 | Header 顺序、重复头、媒体类型、Content-Length 形状、协议版本 | 浏览器升级会变化；必须保留基线 |
| 行为 | 请求节奏、突发性、路径熵、ID 枚举、查询变体、404/403 比例 | 低频慢速可能长期低于阈值 |
| 会话 | Cookie 是否存在（不采集值）、会话复用、来源变化 | 匿名 API 可能天然无 Cookie |
| 结果 | WAF 命中、认证失败计数、上游拒绝、蜜罐命中 | 认证结果需要可信上游信号 |
| 外部 | IP/ASN 信誉、云主机标记、代理池 | 共享 NAT 和云服务会扩大误伤 |

### 7.3 分级处置

```text
observe      记录、采样、建立基线，不影响请求
challenge    验证码/工作量证明/额外认证（可选，按业务）
suspect      短时精确限速，禁止大范围封禁
confirmed    精确 IP 封禁 + tarpit + 告警
campaign     前缀/ASN 级处置，只能人工批准或高门槛自动策略
```

默认生产策略：

- 已知高危请求特征可以立即阻断请求本身。
- 行为异常至少需要两个独立信号类别，且持续窗口达到门槛，才进入 `suspect`。
- 自动封禁默认只封精确 IP，TTL 有上限，默认不超过数分钟到 15 分钟，并可在管理面撤销。
- `/24`、`/64`、ASN 只用于检测和聚合，不默认用于封禁。
- 共享 NAT、企业出口、搜索引擎、监控和已认证服务使用显式豁免；豁免不能按 UA 单独授予。
- 新部署先运行 observe/monitor，收集基线和误伤样本，再由配置晋级到 enforce。
- 所有封禁、延长、撤销、tarpit 和降级都写入审计并带规则 ID。

### 7.4 低误伤的硬约束

- **封禁键与关联键分离**：actor 检测可以使用来源前缀关联；封禁键默认是精确 IP + 稳定形状，不直接使用 `/24` 或 `/64`。
- **先请求级、后来源级**：能阻断一个危险请求时，不先封整个来源。
- **先短时、后延长**：首次确认使用短 TTL；重复确认才允许延长，延长必须有次数上限。
- **可解释**：每次处置输出信号列表、阈值、窗口和规则版本，不能只输出一个黑盒分数。
- **可回滚**：管理面支持按规则 ID、来源和批次撤销封禁，撤销本身也写审计。
- **有误伤预算**：按路由统计正常客户端被阻断、限速、挑战的比例；超过预算自动降级为观察并告警。
- **不把指纹当身份**：JA3/JA4、H2 指纹和 UA 都不能单独触发来源封禁。

## 8. Safe Ops：危险指令拒绝

### 8.1 目标

Safe Ops 假设操作者会犯错，AI Agent 会误判，网页、日志、Issue、聊天内容和模型输出都可能包含提示注入。它的职责不是让 Agent 更聪明，而是让危险动作无法仅凭自然语言或模型自信被执行。

### 8.2 两个层面

**请求层**

- 默认拒绝 `TRACE`、`CONNECT`、代理型绝对 URI、非法方法和未声明的升级。
- 对 `/admin`、`/backup`、删除、审批、转账、配置变更等高风险前缀使用独立路由策略。
- `read_only` 只能按 HTTP 方法降低写风险；GET 有副作用时必须在业务侧修正语义。
- 管理面默认关闭且只允许回环；不能把管理端口通过反向代理、端口转发暴露到公网。

**运维层**

- 所有部署、升级、回滚、证书、防火墙、磁盘和配置操作经过 Safe Ops。
- 模型可以提出计划，但不能批准自己的计划；执行器只接受通过服务端策略校验的意图。
- 原始 shell 默认拒绝；优先使用类型化动作和受限参数 schema。

### 8.3 风险分级

| 等级 | 示例 | 默认策略 |
|---|---|---|
| R0 只读 | 查看状态、读日志、读取配置摘要 | 认证后允许，仍写审计 |
| R1 可逆低风险 | 生成配置草稿、dry-run、导出报告 | 需要预览和明确确认 |
| R2 破坏性可回滚 | 替换配置、重启服务、轮换证书、清理缓存 | 默认拒绝；要求目标核验、备份、确认、回滚方案 |
| R3 不可逆/大范围 | 删除数据、格式化磁盘、清空备份、改防火墙、删除证书/密钥 | 默认拒绝；仅离线 break-glass + 双人批准 |

### 8.4 执行前检查

- 目标必须是规范化绝对路径或明确资产 ID；拒绝通配符、未展开变量、相对路径和歧义目标。
- 拒绝路径穿越、符号链接、Windows junction/reparse point、设备路径、UNC 路径和跨出授权根的路径。
- 磁盘、卷、分区、远程主机和证书必须按序列号、指纹或稳定 ID 核验，不能只按显示名称。
- 执行前生成计划摘要和影响范围；批准绑定到计划哈希、环境、时间窗口和 nonce，不能重复使用。
- 要求备份或快照时，先验证备份可读、可恢复，再允许执行。
- 任何密钥都不能出现在命令行参数、日志或模型上下文；通过 stdin、受限环境或密钥管理器注入。
- 高风险动作必须有独立验证步骤；实际结果与预期不一致时停止并回滚。

### 8.5 审计与 break-glass

- 记录谁提出、谁批准、批准时间、目标、计划哈希、执行器、结果和回滚结果。
- 审计不可用时拒绝执行，而不是继续操作。
- break-glass 使用离线签名、一次性令牌、短有效期、双人批准和明确事故编号。
- break-glass 不能变成通用后门；每次使用自动生成复盘任务和告警。

## 9. 状态、策略和失效模式

### 9.1 单写者

- `offenders.json` 只能作为单机过渡存储；迁移到版本化状态服务后，必须只有一个写者。
- 两个 L7 核心不能同时写同一份封禁文件，也不能各自维护一套相互覆盖的全局封禁。
- 多节点使用 fencing token/租约，过期 leader 不得继续写入。
- 状态记录包含版本、来源节点、创建时间、过期时间、规则 ID、信号和审批引用。

### 9.2 故障矩阵

| 故障 | 请求路径行为 | 运维行为 |
|---|---|---|
| 配置无效 | 启动失败；运行中重载失败保留旧配置 | 拒绝晋级 |
| 审计不可写 | 保护路由返回 503，直到恢复 | 拒绝执行新的高风险操作 |
| 策略服务不可用 | 使用已签名且未过期的本地策略快照；快照过期则拒绝 | 停止发布新策略 |
| 风险状态不可用 | 保留最后已知本地封禁；停止新的跨节点自动封禁 | 告警，禁止手工大范围封禁 |
| Redis 不可用 | 清理本地缓存不等于清理封禁；保留最后已知状态 | 不修改数据面为全放行 |
| 告警不可用 | 请求继续，记录失败指标 | 外部心跳告警；不能声称告警正常 |
| 证书无效/过期 | 新握手拒绝 | 旧连接按策略排空，回滚证书 |
| 时间源异常 | 使用单调时钟做窗口；审计记录 UTC 和偏差告警 | 停止依赖绝对时间的危险操作 |

告警是唯一有意不阻塞请求的例外：它的作用是通知，不是授权。告警失败不能改变请求 allow/deny，但必须被独立监控。

### 9.3 策略快照

- 策略由 Python 服务编译成带版本、哈希和签名的快照。
- 原生核心只有在验签通过、版本单调、未过期时才加载。
- 快照加载失败保留旧快照；旧快照过期后按失败关闭处理。
- 配置 diff 必须能识别关闭 WAF、放宽 ALPN、扩大允许来源、关闭审计、放宽封禁范围等安全降级。

## 10. 分阶段交付

### 阶段 0：当前版本安全加固

- 保留现有 H1 严格解析和 WAF/DLP。
- 管理面保持默认关闭、只回环；审计和告警链路做故障演练。
- 增加 Agent 观察基线、误伤指标、规则解释和安全降级检查。
- Safe Ops 先以独立策略规格和只读预演落地，不开放全自动执行。

### 阶段 1：B+D-1 快速 L5 入口（已实现）

- L5 终止客户端 TLS，计算标准和项目指纹，执行 SNI/ALPN/mTLS 策略。
- H1 进入 Python HighWall；H2/H3 如已接入原生检查器则进入原生路径，否则明确拒绝或标注为 C1/C2。
- 不在 HAProxy 终止 TLS 后再声称拿到了真实客户端 JA3/JA4。
- 所有流量先走 observe/影子，再按路由逐步启用封禁。
- 当前 `l5wall serve` 只允许回环监听和回环上游，只接受 `http/1.1` ALPN，并在首个请求头执行 SNI/Host 一致性、framing 和资源上限检查；H2/H3 仍会在 ALPN 阶段被拒绝。

### 阶段 2：原生 H1 + L5 影子（原生 H1 已独立实现，生产影子切换未完成）

- 原生核心完成 H1 严格解析、资源预算、响应 framing 和审计。
- 与 Python 核心并行比较 allow/deny、规则 ID、状态码和审计字段。
- Python 仍是权威决策；原生只观察，不写封禁。

### 阶段 3：H2、WebSocket、gRPC（H2/gRPC 达到 C3，WebSocket 端到端待补）

- 完成 H2 帧/流状态机、Rapid Reset、CONTINUATION、HPACK 和流控测试。
- 完成 WebSocket 显式路由和有界消息检查。
- 完成 gRPC trailers、压缩、deadline 和状态处理。

### 阶段 4：H3/QUIC（达到 C3，C4 与高强度 QUIC 预算测试待补）

- 完成 QUIC 地址验证、Retry、0-RTT、迁移、QPACK 和 H3 控制流。
- 做 UDP 放大、握手并发、包预算和连接迁移测试。
- 只有 C3/C4 门槛通过后才对外声明完整 H3 防护。

### 阶段 5：B+D-4 切换（原生数据面已可独立运行，生产切流与单写者未完成）

- 原生核心成为唯一数据面执行者。
- Python 降级为策略编译、复杂检查、测试 oracle 和运营分析。
- 单写者状态服务接管封禁；旧 `offenders.json` 只读迁移。
- 保留 H1 Python 回退路径至少一个稳定版本，设定明确退役条件。

## 11. 测试与验收

### 11.1 协议与资源

- H1：CL/TE 冲突、重复头、obs-fold、非法 chunk、超长行、慢速发送、响应分帧。
- H2：Rapid Reset、CONTINUATION flood、HPACK bomb、窗口耗尽、h2c、非法 SETTINGS、流状态、GOAWAY。
- H3：Initial 放大、Retry、0-RTT 重放、连接迁移、QPACK 阻塞、非法控制流。
- TLS：TLS 1.0/1.1 拒绝、SNI/Host 不一致、未知 ALPN、mTLS 失败、证书过期、密钥轮换。
- 所有解析器必须有大小上限、深度上限、超时和 fuzz 测试；不能 panic 或无限分配。

### 11.2 低误伤

- Chrome、Firefox、Safari、移动端浏览器、curl、Go、Node、Python 客户端矩阵。
- H1/H2/H3、WebSocket、gRPC、流式响应和长连接。
- 共享 NAT、企业代理、IPv4/IPv6、云主机和搜索引擎流量。
- 正常客户端被阻断、限速、挑战的比例按路由统计；超过预算降级观察。

### 11.3 Safe Ops

- 删除、格式化、覆盖、改防火墙、删证书、删备份、改 ACL、清理日志。
- 路径穿越、符号链接、junction、UNC、通配符、变量注入、命令注入、Unicode 混淆。
- 提示注入、伪造批准、重放 nonce、过期批准、Agent 自批准、额度耗尽。
- 备份不可读、回滚失败、审计中断和审批服务不可用。

### 11.4 发布门槛

- 未授权请求不能到达上游。
- 未知 ALPN 不回落；SNI/Host 不一致拒绝；0-RTT 默认拒绝。
- H2/H3 攻击流量不能耗尽流、内存或慢速槽位。
- 自动封禁不扩大到未配置的前缀或 ASN。
- 审计中没有 Cookie、Authorization、原始查询串或请求体原文。
- 策略、审计、审批不可用时失败关闭。
- 所有部署验收只使用回环或临时端口；修改防火墙、端口转发和生产配置必须单独确认。
- 首轮 DSH AI Agent 隔离靶场验收、r5 定向复测和 r6 HWA-11 窄范围复测已完成；结果见 [DSH-R6-RESULTS-20261101.md](DSH-R6-RESULTS-20261101.md) 与 [DSH-R5-RESULTS-20261101.md](DSH-R5-RESULTS-20261101.md)，历史修复记录见 [DSH-REMEDIATION-20261101.md](DSH-REMEDIATION-20261101.md)，完整验收范围和门禁见 [DSH-SECURITY-ACCEPTANCE.md](DSH-SECURITY-ACCEPTANCE.md)。DSH 只报告，不直接改代码，完整残余项仍需人工复核后才能进入生产发布结论；DSH 对生产发布仍建议 no push，公开源码与脱敏记录的推送已获单独授权。

## 13. 风险与待决策

### 已知残余风险

- JA3/JA4、H2、QUIC 指纹都能被复用或伪造，不能当身份。
- 低频、慢速、白盒了解策略的 Agent 可能长期低于阈值。
- 共享 NAT、代理池和云服务会同时扩大误伤与漏报。
- H3 指纹和 QUIC 检查的实现复杂度高，错误实现本身可能成为攻击面。
- 应用认证、授权和业务逻辑漏洞仍必须由上游负责。
- 第三方组件和许可证需要单独审计；JA4H 等标准的商业使用许可要核对。

### 建议的工程决策

- **原生核心语言**：最终推荐 Rust，理由是内存安全、资源边界明确和适合长期维护；Go 可作为过渡原型，但要接受 GC 和运行时边界。若进度优先，可在阶段 1 使用 Go，最终仍收敛到单一原生核心。
- **H3 实现**：使用原生 QUIC/H3 栈；CDN 终止且不提供可信原始指纹时，只能算外部防护，不算 B+D-4 的 L5 覆盖。
- **状态后端**：单机 SQLite WAL；多机 Redis 或专用状态服务；始终单写者。
- **Safe Ops 位置**：独立控制面/独立进程，不嵌入请求解析器；通过类型化 API 和签名审批连接。
- **管理面**：保留回环 + OS ACL + token；远程管理走 VPN 或私网 mTLS，不暴露公网。
- **策略服务**：本地签名快照优先，Python 服务不在每个请求的同步关键路径上。
