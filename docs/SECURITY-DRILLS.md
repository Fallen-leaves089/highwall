# HighWall 授权安全演练记录

版本：`0.10.0`
范围：HighWall 的 HTTP 入口边界
性质：维护者在隔离实验环境中执行的三轮授权黑盒演练

## 0. 披露原则

本文只保留演练范围、配置差异、防守结论和残余风险。以下内容有意省略：

- 靶场地址、端口、完整 URL、报告与日志路径；
- 任何 flag、会话标识、凭据或可复用载荷；
- 具体规则编号、精确阈值和敏感路径清单；
- 绕过步骤或可直接复现的攻击配方。

这样做的目的是让防守方能判断控制是否有效，同时不把演练记录变成攻击手册。

## 1. 范围与方法

- 三轮均为隔离的本地实验环境，上游为模拟服务，不连接真实设备、生产系统或外部网络目标。
- 采用黑盒方式，只从 HTTP 客户端视角发起请求，不依赖源码级白盒信息选择路径。
- 测试对象是 HighWall 的请求解析、路径规范化、路由、WAF、响应扫描、限流、封禁和蜜罐行为。
- 不测试上游业务逻辑漏洞、主机提权、内网横向移动、DNS 隧道或非 HTTP 服务。
- 成功标准是取得预设 flag；三轮均未取得。

## 2. 轮次配置

| 轮次 | 主要变更 | 目的 |
| --- | --- | --- |
| 第一轮 | 默认防护基线，蜜罐关闭 | 建立基线，确认主要攻击类别是否被拦 |
| 第二轮 | 开启蜜罐与首击封禁，收紧自动封禁 | 验证诱捕、来源关联和分层响应 |
| 第三轮 | 关闭蜜罐，保留其余防护 | 单独测量第二层防御，排除蜜罐干扰 |

第二轮与第三轮之间只改变蜜罐相关配置，其他字段保持一致，便于比较。

## 3. 结果摘要

第一轮（约 330 次请求）：

- 未取得 flag。
- 路径穿越、SQL 注入、跨站脚本、Host 伪造、非允许方法和不符合要求的 Content-Type 均被拒绝。
- 集中请求下限速生效。
- 观察到部分错误响应暴露了比必要更多的实现信息，已列入修复项。

第二轮（约 800 次请求，蜜罐开启）：

- 未取得 flag；模拟上游没有收到路径穿越请求。
- 配置的诱饵路径返回静态诱饵内容，未访问上游，也未反射输入。
- 命中蜜罐后来源进入短时封禁；集中违规进一步触发自动封禁。
- 未信任任何转发头来源时，伪造转发头不改变 HighWall 判定的客户端地址。
- 诱饵内容与真实业务无关，未包含凭据或内部信息。

第三轮（约 140 次请求，蜜罐关闭）：

- 未取得 flag；0 次 5xx，0 次 429。
- 路径、协议版本、请求体 framing、会话和方法边界均未发现绕过。
- 本轮请求速率较低，未观察到限流触发。这不能推断限流不存在或无效；限流已由第一轮的集中请求以及单元和集成测试覆盖。

## 4. 本轮修复

演练暴露的问题已在 `0.10.0` 处理：

- 405 响应补齐 `Allow`，代理级、路由级和管理面分别返回实际允许的方法。
- `/reload` 管理端点的 405 同样带 `Allow: POST`。
- 配置检查新增提示：启用 `allowed_origins` 且允许写方法、但未允许 `OPTIONS` 时，浏览器预检会被拒绝。
- 相关行为已加入回归测试。

## 5. 残余风险

- **归一化一致性**：百分号解码和 Unicode 归一化发生在路由与鉴权之前。当前 WAF 与应用消费同一份归一化结果，因此未出现判断分歧；若拆分为多层独立实现，必须保证两层归一化语义一致，否则可能出现一层放行、另一层拒绝的差异。
- **共享 NAT 误伤**：按来源 IP 的封禁和限速会连带影响 NAT、代理池或办公网出口后的正常用户。上线前应按真实来源评估阈值，并保留人工解封路径。
- **低频定向 Agent**：轮换请求形状、控制速率并了解策略的自动化客户端可以长期低于指纹和评分阈值。指纹是风险关联信号，不是身份。
- **同主机失陷**：攻击者取得运行主机权限后，可以读配置、修改二进制或绕过代理直连上游。HighWall 不能建立这条边界。
- **蜜罐诱饵**：诱饵不得包含真实凭据、Cookie、私钥或可横向移动的内网信息；蜜罐路径本身也可能被指纹识别。
- **启发式边界**：WAF、DLP、评分和蜜罐都会漏报和误报，不能替代认证、授权、上游审计和外部速率控制。

## 6. 结论与边界

三轮演练支持以下有限结论：

- 在测试配置下，主要 HTTP 层攻击类别没有取得 flag，也没有让穿越请求到达模拟上游。
- 蜜罐、自动封禁和限流可以组合成分层响应，但每一层都有明确适用范围。
- 关闭蜜罐后，其余防护仍能维持基线；低速率测试不足以评价限流强度。

这些结论不外推为“无漏洞”或“生产可直接使用”。演练是维护者自测，不是独立第三方审计，也不构成性能、容量或 SLA 承诺。真实部署仍需按 [`THREAT_MODEL.md`](THREAT_MODEL.md) 和 [`DEPLOYMENT.md`](DEPLOYMENT.md) 做环境化验证。
