# L4Wall 威胁模型

版本：`0.1.0`。本文描述 L4Wall 保护什么、不保护什么，以及为什么 L4 的 Agent 判定只能是启发式。

## 目标

L4Wall 的目标不是让上游应用“自动变安全”，而是在 TCP 连接进入业务协议之前维持一组明确、可测试、默认拒绝的不变量：

1. 只有配置过的监听端口会被代理；
2. 来源地址必须满足 CIDR 策略，拒绝规则优先；
3. 单来源和全局并发、新建连接速率有上限；
4. 首字节、空闲和总连接时长有上限；
5. 单向字节数有上限；
6. 连接行为达到阈值时按模式记录、延迟或拒绝；
7. 允许、拒绝、限速、封禁和关闭原因写入有界 JSONL 审计；
8. 审计写入失败时默认拒绝新连接；
9. 管理面只绑定回环地址并要求 Bearer token；
10. 共享封禁故障时本地封禁不丢失、不缩短，数据面不被同步任务拖垮。

## 资产

- 上游服务的可用性和连接槽位；
- 网关进程的 CPU、内存、文件描述符和连接表；
- 配置、封禁名单和审计记录的完整性；
- 来源 IP 的隐私（审计默认记录 IP，可关闭）。

## 信任边界

```text
不可信客户端 / 攻击 Agent
        |
        |  TCP 连接、来源地址、连接时序
        v
  L4Wall 进程（可信计算基）
        |
        |  仅允许 L4Wall 访问的上游连接
        v
  HighWall / 上游应用

私网 Redis（可选）
  -> L4Wall 只读、增量导入共享封禁
```

- L4Wall 只信任自己的配置、进程内存和本机回环管理面。
- 来源 IP 由操作系统提供；L4Wall 不验证源地址真实性，也不处理伪造源 IP。
- 如果 L4Wall 与上游在同一主机且上游监听 `0.0.0.0`，攻击者可能绕过网关直连上游。部署必须让上游只监听 L4Wall 可达的地址，或用主机防火墙限制。
- 可选的私网 Redis 属于共享状态源，不属于数据面。L4Wall 只接受版本化 JSON，并且只把远端数据当作增量；Redis 的可用性和内容完整性会影响封禁新鲜度，但不能改变本地失败关闭语义。

## 攻击者能力

在范围内，假设攻击者可以：

- 从远端发起任意数量的 TCP 连接；
- 扫描多个端口，进行多 listener 扇出；
- 建立后立即关闭、发送极少字节或长时间不发送；
- 控制连接间隔，模仿固定节奏或随机节奏；
- 轮换来源 IP，使用 NAT、代理或住宅代理；
- 触发上游错误和连接重置；
- 读取公开文档和默认配置。

不在范围内，假设攻击者：

- 已取得 L4Wall 进程所在主机的 root/管理员权限；
- 能读写 L4Wall 进程内存、配置目录或审计文件；
- 能控制运营商链路或清洗设备；
- 能伪造大量源 IP 发起带宽型 SYN flood。

## 威胁与控制

| 威胁 | L4Wall 的控制 | 边界 |
|---|---|---|
| 端口扫描 / 多端口扇出 | 只代理显式 listener；按来源统计 distinct listener 数并评分 | 未配置端口不由 L4Wall 观察；全端口扫描仍需主机防火墙 |
| 新建连接洪泛 | 全局/单 IP 并发上限、单 listener 令牌桶 | 不替代内核 SYN 队列、CDN 或运营商清洗 |
| 慢连接 / 半开占用 | `first_byte_timeout`、`idle_timeout`、`max_connection_seconds` | 已完成握手的慢连接可被回收；未完成握手的 SYN flood 看不到 |
| 短连接高频重连 | 连接时长/字节阈值评分、拒绝风暴信号 | 正常健康检查也可能触发，需要调阈值 |
| 零字节探测 | 已接受但双向零字节的连接计数 | 某些协议先由服务端发言，可能误报 |
| 固定节奏 Agent | 连接间隔变异系数评分 | 随机化节奏、低频慢速可绕过 |
| 封禁规避 | 可选 `/24`、`/64` 聚合封禁；持久 `offenders.json` | NAT/代理共享会误伤；聚合前必须确认网段归属 |
| 审计被淹没 | JSONL 轮转、有界字段、无 payload | 不保证抗磁盘写满；需外部监控 |
| 审计写入失败 | 默认 `fail_closed`，停止接受新连接 | 进程仍可能在旧连接上工作；需外部告警 |
| 管理面暴露 | 只允许回环绑定；Bearer token 从环境变量读取 | token 泄露后本机用户可读管理面；需文件/进程权限保护 |
| 共享封禁污染/故障 | 私网限制、严格版本与字段校验、前缀/TTL/容量上限、本地优先合并 | 有权写 Redis 的一方仍可制造误封；读取端不会验证共享源的身份 |
| 配置错误 | 严格 schema、未知字段拒绝、`check`/`inspect`、可选强制白名单 | 不能判断业务上“这个上游是否该被暴露” |

## Agent 判定的含义

L4 没有 HTTP header、Cookie、路径或 User-Agent。L4Wall 的 `agent_like` 只表示“连接行为像自动化探测”，不表示“已识别出某个 AI Agent”。

当前使用的信号：

- `connection_burst`：窗口内连接数超过阈值；
- `listener_fanout`：同一来源在窗口内访问多个受保护 listener；
- `short_connections`：大量连接持续时间短且字节数极少；
- `zero_byte_probes`：已接受但双向零字节的连接；
- `rejection_burst`：窗口内被拒绝次数超过阈值；
- `regular_timing`：连接间隔变异系数低于阈值。

评分达到 `score_threshold` 或满足 `agent_min_signals + agent_score` 后进入 `suspected`；达到 `confirm_score` 或持续疑似超过 `confirm_after_seconds` 后进入 `confirmed`。`mode=score` 只记录，`throttle` 延迟，`block` 拒绝并封禁。

这不是身份认证，也不是安全边界。一个会控制速率、随机化间隔、复用正常连接或使用住宅代理的 Agent 可以绕过这些启发式。不要把 `agent_confirmed` 当作“已确认攻击者身份”的证据。

## 失败关闭语义

- 配置缺失、JSON 非法、未知字段、重复端口、非法 CIDR、非回环管理面：拒绝启动。
- 审计文件无法打开或写入，且 `on_write_failure=fail_closed`：`healthy=false`，新连接被拒绝。
- 上游连接失败或超时：关闭本次会话并记录 `upstream_error`，不转发未验证数据。
- 首字节/空闲/总时长/字节上限触发：关闭会话并记录原因。
- offender 文件损坏：启动失败，避免静默丢弃封禁名单。
- 显式封禁（本地或共享）优先于评分开关：关闭启发式评分不会释放已知封禁；解除封禁必须删除持久条目或等待 TTL。
- 共享 Redis 不可达、超时、空键、坏 JSON、超大响应或非私网解析：同步任务记录失败，本地封禁和最后已知远端封禁继续生效；不阻塞数据面，不退出主进程。
- 远端条目过期、前缀过宽、字段未知、版本不支持或时间非有限：单条丢弃或整份拒绝，不清空本地封禁，也不扩大封禁范围。
- 远端条目只能新增或延长封禁；本地条目优先占用容量，远端 TTL 受 `max_ttl_seconds` 截断。
- 远端导入后的封禁写入 `offenders.json` 失败：内存封禁仍生效，并记录持久化错误。

## 残余风险

- **误报**：健康检查、监控探针、NAT 后的正常用户可能触发短连接或节奏信号；先用 `score` 模式观察。
- **绕过**：低频、随机、长连接、住宅代理和正常协议行为可以规避 L4 启发式。
- **资源耗尽**：连接上限降低风险，但不能阻止带宽、CPU 或文件描述符被其他方式耗尽。
- **时间与重启**：封禁使用墙钟持久化，评分使用单调时钟；系统时间大幅跳变会影响封禁过期判断。
- **共享源信任**：L4Wall 只限制 Redis 的网络位置和载荷格式，不能证明写入者身份；能写共享键的攻击者可以制造误封。Redis 必须只对可信 Controller/管理机开放。
- **共享延迟**：默认每秒同步一次，封禁生效存在最长约一个同步周期加超时的延迟；Redis 长期不可用时新封禁停止扩散，但已有封禁继续生效。
- **Windows asyncio**：Windows Proactor 在连接重置时可能抛出 `ConnectionResetError`；网关会按 `io_error` 关闭，演示脚本已处理该差异。
- **审计隐私**：默认记录客户端 IP；对隐私敏感的场景设置 `audit.include_client_ip=false`，但会降低溯源能力。

## 不在范围内

- 带宽型 DDoS、SYN flood、运营商侧拥塞；
- 伪造源 IP 的真实来源识别；
- 已失陷主机、进程内存读取、配置/审计篡改；
- HTTP 语义、WAF、DLP、认证授权；
- TLS 终止、SNI 白名单、JA3/JA4 指纹；
- 全端口主机防火墙；
- 上游应用自身漏洞。
