# L5Wall 威胁模型

版本：`0.2.1`。本文描述 L5Wall 保护什么、不保护什么，以及为什么 Python `ssl` 上的握手元数据不能等同于完整 L5 防护。

## 目标

L5Wall 在 L7 解析之前维持一组明确、可测试的不变量：

1. 只有配置的证书和密钥可以终止 TLS；
2. TLS 版本不得低于配置下限；
3. ALPN 必须显式允许，未知协议不回落；
4. SNI 必须存在并由显式白名单匹配，除非配置明确允许无 SNI；
5. mTLS 模式与客户端证书必须符合配置；
6. 握手有硬超时，失败关闭；
7. 只输出最小化的 L5 元数据，不保存证书原文或密钥；
8. 策略实现不使用 UA、Cookie 或应用层内容做“身份认证”；
9. `serve` 只接受回环地址、显式 H1 ALPN、有界首请求头，并校验 SNI/Host 一致；连接数、空闲时间和单方向字节有上限。
10. 瞬时 accept 错误不得结束监听器；不可恢复错误必须显式失败；停机时在有限时限内排空在途连接。

## 信任边界

```text
不可信客户端
  |  ClientHello、SNI、ALPN、可选客户端证书、握手时序
  v
L5Wall 进程（可信计算基）
  |  认证后的 TLS 连接 + L5 元数据
  |  首 H1 头预检 + SNI/Host 一致性 + 资源上限
  v
HighWall L7 数据面（回环或同主机私有链路）
```

如果 TLS 在 CDN、HAProxy、Envoy 或云负载均衡处终止，L5Wall 只能看到转发后的连接，不能声称掌握真实客户端的 ClientHello、SNI、ALPN 或证书。部署必须先明确 TLS 终止点。

## 攻击者能力

范围内假设攻击者可以：

- 发送任意 ClientHello、SNI、ALPN、证书链和握手分片；
- 建立大量半开或慢握手连接；
- 轮换 IP、代理和 TLS 栈；
- 伪造或复用浏览器指纹；
- 读取公开配置和文档。

不在范围内假设攻击者：

- 已取得主机 root/Administrator；
- 能读取进程内存、私钥或替换证书；
- 能控制运营商链路或实施带宽型 DDoS；
- 能在 L5 之后注入不受 L7 策略检查的应用内容。

## 威胁与控制

| 威胁 | 当前控制 | 边界 |
|---|---|---|
| 降级到旧 TLS | `minimum_version` | 只覆盖本进程终止的连接 |
| 未知 ALPN 回落 | `allowed_alpn` 白名单；不匹配拒绝 | 不解析 H2/H3 帧 |
| 任意 SNI 探测 | `allowed_sni`；默认要求 SNI；serve 校验 SNI/Host 一致 | 只校验首个 H1 请求，不替代 HighWall 解析 |
| 无证书 mTLS 绕过 | `mtls_mode=required` + 客户端 CA | CA 文件被替换时边界失效 |
| 慢握手或慢连接占用 | `handshake_timeout`、连接槽位、`idle_timeout`、单方向字节上限 | 无握手前 TCP 并发/包预算，不能替代 L4Wall/内核防火墙 |
| 证书/私钥泄露 | 严格路径检查、inspect 不输出密钥内容 | 文件权限和主机安全由部署者负责 |
| 客户端指纹伪造 | 只把元数据作为策略输入，不单独当身份 | 没有 JA3/JA4，不能识别复用 TLS 栈 |
| 反复重连触发监听错误 | 瞬时错误分类、50 ms 至 1 s 指数退避、成功后退避复位 | 持续资源耗尽仍会降低接纳能力，需 L4Wall/内核限制连接和文件描述符 |

## 失败关闭语义

- 配置缺失、重复键、未知字段、证书/私钥不可读或 mTLS 组合非法：配置检查失败。
- TLS 握手错误或超时：关闭连接，抛出 `L5HandshakeError`。
- 版本、ALPN、SNI 或 mTLS 策略不满足：关闭连接，抛出 `L5Denied`。
- 不支持的 ALPN 不会回落到 `http/1.1`。
- 监听器遇到 `EINTR`、连接中止、Windows socket reset、文件描述符或缓冲区耗尽等瞬时错误：记录告警并退避重试，监听器继续存活。
- 监听器遇到不可恢复错误：显式抛出 `L5ProxyError`，不会静默返回后伪装成正常进程。
- 收到 `SIGTERM`：停止接受新连接，在 `shutdown_timeout` 内等待在途连接；超时后强制关闭。

## 残余风险

- Python `ssl` 不暴露完整 ClientHello 字节流，无法在运行时可靠计算标准 JA3/JA4。
- 当前没有 0-RTT、会话票据策略、连接迁移和 QUIC 控制。
- 没有握手前 TCP 槽位、CPU、内存或包预算，不能替代 L4Wall/内核防火墙。
- serve 的 SNI/Host 一致性只覆盖首个 H1 请求头，不覆盖后续请求、H2/H3、证书 SAN 或业务身份；需要 L7 继续校验。
- serve 只监听回环且不传递原始客户端 IP；部署者不得据此启用按 IP 封禁、来源 ACL 或依赖真实来源的限速，除非另有可信身份通道。
- 该实现尚未经过独立第三方审计。
